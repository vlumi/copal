# Plan: the oracle, finished

The oracle runs every program of both specimens on cases found from their decision tables, and Pangaea's jobs as batches on those cases. What is left is Laurasia's batch, which is run by shell scripts rather than JCL, and the 95 rules no case reaches. Most of those are rules a run could take, given a file that fails or data no clean case holds, or rules the survey could show no run can take, given what a called program returns.

Read [oracle.md](oracle.md) and [deterministic-sweep.md](deterministic-sweep.md) first; their ground rules apply. Facts only, goldens with the change that causes them, a test for every step, `make ci` before pushing, and no special case for either specimen.

## Parts

1. **A batch of Laurasia's scripts.** `survey oracle -jobs` takes scripts as well as jobs, and runs them as they are run, with sh, on inputs from the programs' cases.

   As built: the scripts run with sh, in the order given, on directories of their environment that the scripts before them wrote to. A variable of the environment that names the directory of what a step runs, `LCS_BIN` or `LCS_SCRIPTS`, names the oracle's stand-ins instead. These run the program, the script, `sort` or `mv` with a program's trace in a file named after its process, and record how each ended, so each step has an outcome without the oracle reading the scripts' own logs. A file a script reads that nothing before it wrote takes the records of the cleanest case of the first program that reads it, through a sort or a move between them. A parameter takes the command line of the cleanest case of the first program it is passed to, the only value that case is consistent with, and the variable that stands for it, `DATE`, has one value across the batch. Laurasia's cases leave the date blank wherever no rule needs it, so the batch runs with a blank date, and its file names show it. `make oracle` runs open, nightly and cycle; every step of the night runs, and open ends with ACCTLD's return code 8, as its one case does.

   Searching Laurasia again showed that CLRIN's checked-in cases were older than the search: a change since had altered what it finds, and the cases had been replayed but not searched again. They are searched again in their own commit, and reach the same rules.
2. **I/O errors.** Cases that fail a file on purpose, the same way every time: a file that is missing, or a record of the wrong length. They reach the rules that only a file status other than success takes.

   As built: three levers for each file, tried after the changes to records, and one failure a case. A file a program reads may be missing, so that opening it fails with status 35; a sequential one may be a directory, so that it opens and reading it fails with status 30; and a file it only writes may be bound to a path in a directory that is not there, so that creating it fails with status 30. GnuCOBOL gives the same statuses on macOS and on Linux, through the same indexed file handler. A record of the wrong length was left out: GnuCOBOL reads a short record of a fixed-length file without an error, and a long line of a line sequential one with status 06, which no program tests. A case records its failure in `input/failed.txt`, and a batch never takes its inputs from one. The rules reached go from 413 to 437 of 508: every rule that only a file status other than success takes is reached, 24 in all, and 71 rules are left.
3. **What a called program returns.** A field the called program sets is carried back into the caller, so that a combination of conditions no call can return is left out of the caller's rules, as one no path can take is.

   As built, this part found something else. AUTHSRV's unreached rules were not about what its called programs return. Most were paths that contradict themselves within AUTHSRV, and the rest were rules the search did not reach. Three changes, each with its goldens:

   - **An AND or OR holds for its parts.** A path that found an AND true has every part true that nothing since may have changed, an OR found false every part false, and an AND found false cannot have every part found true later. A comparison with a literal is known false where a test found the field not to have that value. AUTHSRV's and CLRIN's tables lose 12 rules no run can take.
   - **A condition tested holds within a later one.** A part of a later condition the path has already tested, with nothing changed since, has the outcome found. TXVALID's tables lose 2 rules.
   - **Levers through what a called program computes.** A condition of a called program on an item it computes takes levers on the caller's input fields the item comes from, through the items passed, and an item a FUNCTION MOD or REM divides takes the divisor as a value to try. ATMWDL now approves a withdrawal, and AUTHSRV's cases reach 6 more rules.

   The rules reached go from 437 of 508 to 443 of 494, and 51 are left. What a called program returns is still not carried back: AUTHSRV's three rules that find a request approved after a paragraph that only declines are the one kind left that it would rule out. IXFEE's six rules on a group out of range are the other side, values no caller passes.
4. **Totals that agree by construction.** Rules that only bad data reaches, such as totals that disagree when the program computed both, listed apart from the rest, with the reason.

   As built: a rule no case reaches is marked when it finds two totals the program adds up itself to differ: an equality, found false, of two items of the program's working storage that it only ever adds to, from zero. No input field sets either, so the search has nothing to change to reach the rule; it takes the program's own arithmetic disagreeing with itself. The cases' README says so in the rule's cell, and `coverage.json` lists the rules as `ownTotals`. Three are marked: GLSUM's debits and credits, ACCTMNT's balances in and out, and STMTPRT's statements selected and printed. The mark says why the search cannot reach a rule, not that no run can: it is no proof that the totals always agree.

Each part one pull request.

## After the parts

The 48 rules left after part 4 were taken in kinds, a pull request each.

1. **What a path knows when it starts.** A pass through a loop knows the loop's UNTIL condition false, unless the loop tests it after each pass. A paragraph entered by PERFORM alone, and by no GO TO, THRU range or fall-through, knows the outcome of each condition it tests that every path to every PERFORM of it knows the same. The first paragraph of a program entered once a run, one nothing calls with items and that never returns to a caller, knows the values its working storage starts with. And a statement's own change, beside the paths through its AT END or WHENs, no longer counts what those run. TXVALID's tables lose 4 rules that found the file bad where it cannot be, and GLSUM's one that found transfers in transit with no month closed: 443 of 489 rules are reached, and 43 are left.
2. **What a PERFORM leaves in a field.** A statement whose every statement that may change a field, at any depth of what it performs, gives the field a literal leaves it one of those values or what it had before. A MOVE of SPACES to a group blanks the fields of text it holds. AUTHSRV's tables lose the 3 rules that found a request approved after a paragraph that only declines, and DISPUTE's the one that found a case no longer held after an event that can only hold one: 443 of 485 rules are reached, and 39 are left.
3. **A write or rewrite by key that fails.** A rule no case reaches that finds a WRITE or REWRITE by key to fail, its INVALID KEY raised, is marked, as the totals are, and `coverage.json` lists it as `failedWrites`. The search fails a file only when it is opened or read, and a program that writes keys it made new, or rewrites the record it read, meets that failure only when something else changes the file meanwhile. Nine are marked: AUTHSRV's four, CYCLE's three and POST's two. 30 rules are left.
4. **Data the search had not made.** A record that redefines another now shares its bytes in the dataflow, so a month moved in as a number is traced to the date it came from. The base case's records find each other: a record whose bytes the file leaves FILLER, moved whole into a record as long, is laid out with that record's fields, and a field of text compared with another input's key starts with the key's value. And the search has more levers: the condition names of a table's entry, each item given only its own; the digits of a date, the month alone; one whole unit, above and below, for a number with decimals, which survives rounding; an input's records repeated to one past a count the program compares; and the records of one type made of none. INTACCR's tables are all reached, TXVALID's too, and GLSUM's, STMTPRT's and ACCTMNT's one each more: 453 of 485 rules are reached, and 20 are left.
5. **What a copy, or a number moved into digits, tells.** A field moved from another laid out alike holds its value while neither changes, so a comparison of the two is decided, and so is an equality of one with a field a test found less than the other. A whole number moved into a field of digits gives the fields of digits over its bytes their digits, through a redefinition too. ACCTMNT's tables lose the 2 rules that took the lower key as the active account and found it the master's anyway, or the other way round, and GLSUM's and STMTPRT's the one each that found the closed month December with no month closed: 453 of 481 rules are reached, and 16 are left. MONCHG's 3 would take what a paragraph leaves when it returns, carried to where it is performed next; IXFEE's 6 values no caller passes; and the 7 others are GLSUM's transfers in transit that do not net to zero, two, and an account its ledger does not have, a sort in STMTPRT and a read in CLRIN that fail partway, a fee POST's called program returns, and one of ATMWDL's the search has not reached.
